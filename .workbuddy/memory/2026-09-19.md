### 落地内容
- 新增 `harness/resilience.py`（零依赖弹性层）：
  - `CircuitBreaker` / `CircuitBreakerSet`：每工具熔断器，状态机 CLOSED→OPEN→HALF_OPEN→CLOSED；`failure_threshold`/`cooldown_s`/`half_open_successes` 可配；`allow()` 在冷却后转 HALF_OPEN 探活；`on_success/on_failure/on_rejected` 计数；`clock` 可注入（demo 用虚拟时钟）。
  - `RateLimiter`：令牌桶，`acquire()` 阻塞到补充（等待=背压）；`capacity`/`refill_per_s`/`clock`/`sleep` 可注入；`stats()` 暴露可用令牌与等待时长。
  - `BackpressureQueue`：`maxsize` 限单回合工具调用准入；溢出即 shed 返回 False，引擎转软失败回灌下一回合；`clear()` 每回合开始重置。
- `engine.py` 三处接入：模型调用前 `rate_limiter.acquire()`（单独 ratelimit span）；工具执行前 `circuit.get(name).allow()` 否则 fast-fail 回灌；随后 `backpressure.admit()` 否则 shed 回灌；工具返回后 `on_success/on_failure`（失败仅重试耗尽后计一次，config 错误`unknown tool`不计），trip OPEN 时写 P6 `store.record_error`。新增 `resilience_report()` 进 `export_trace`。

### 踩坑（重要，下次别再犯）
- `BackpressureQueue.admit()` 初版有 bug：队列满时「丢最旧的腾地方」却仍 `return True` → 背压形同虚设，5 个工具全执行。正确语义是「满了就 `return False` 拒绝新调用」，由引擎转软失败；丢旧会静默丢已承诺要跑的工作。修正后 `circuit_demo` 场景 C 才真正 shed（4 次）并收敛。

## 项目：完成 P8 高级编排

### 落地内容
- 新增 `harness/orchestration.py`（零依赖编排层）：
  - `execute_calls(executor, calls, *, store, task_id, tracer, parallel, max_parallel)`：模型单回合多个独立工具调用用 `ThreadPoolExecutor` 并发跑；每个 worker 线程内记录 `tool` span + `tool_attempt` 事件（P3/P5）；返回 `{tool_call_id: ToolResult}`。
  - `Delegate` 元工具：`run(parent, sub_prompt)` 起一个**嵌套 Engine**（用 `worker_model` + 父 `registry`），叶子节点——不递归委派/无 Critic/无流式/内存态无 store；父引擎记一个 `delegate` span。
  - `HumanInput` 类型别名：`Callable[[str, dict], str]`。
- 引擎主循环重构为 **gate(串行准入: 人在环/委派/护栏/熔断/背压) → execute(并行) → commit(主线程落盘)** 三段式（`engine.py`）。新增 `__init__` 参数 `parallel/max_parallel/human_input/delegate/stream`；`_call_model` 支持流式（`Model.chat_stream`，逐 delta 打印 + 拼回，`tool_calls/usage` 取最后一个 delta）；`_ask_human` 暂停取人答案（无回调则结构化降级）；`orchestration_report()` 进 `export_trace`。
- `tools.py`：`Tool`/`register` 加 `human=False` 标记（人在环识别）。`models.py`：`Model.chat_stream` 默认一次 yield 完整消息；`DummyModel.chat_stream` 按段流式（离线可见）。
- 线程安全改造：`state.py` 加 `threading.RLock` + `check_same_thread=False`，所有读写路径加锁；`tracing.py` 的 `Tracer.record/span` 加锁。这是并行工具执行的前提，且**不破坏事件溯源单写者语义**（落盘仍只在主线程）。
- `__init__.py` 0.7.0 → 0.8.0。
- `examples/orchestration_demo.py`：四场景 A(并行 ~3× 加速: 0.103s vs 0.302s)/B(人在环暂停取答案回灌)/C(委派嵌套引擎算出 42 折回)/D(流式逐字打印且拼装正确)，全部离线 PASS。
- `docs/INTERVIEW_NOTES.md`：补 P8 小节 + 勾掉 P8 + 加编排/线程安全 Q&A + 电梯演讲带 P8。

### 设计要点（面试可讲）
- 编排能力全挂在「gate→execute→commit」骨架上，无新控制流、零新依赖；与 P0–P7 同源（每加一层都是主循环小增强）。
- 并行只发生在「执行」段；准入闸门串行、落盘主线程 → 既拿到并发加速，又不破坏对话日志单写者不变式。线程安全靠给共享状态（`StateStore`/`Tracer`）加锁，而不是改事件溯源语义。
- 委派嵌套引擎是叶子 + 内存态，防止无限递归与跨线程/嵌套簿记。
